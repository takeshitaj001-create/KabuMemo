# KabuMemo デプロイ手順書

## 概要

KabuMemo は以下の2コンポーネントで構成されており、それぞれ独立してデプロイする。

| コンポーネント | 技術 | ホスティング先 |
|---|---|---|
| フロントエンド（SPA） | Blazor WebAssembly (.NET 10) | GitHub Pages |
| API プロキシ | Cloudflare Worker | Cloudflare Workers |

### 公開 URL

| 用途 | URL |
|---|---|
| アプリ（トップページ） | https://takeshitaj001-create.github.io/KabuMemo/ |
| 個別銘柄ページ（例：7203） | https://takeshitaj001-create.github.io/KabuMemo/stock/7203 |
| API プロキシ（Worker） | https://kabumemo-proxy.kabumemo.workers.dev |

---

## Part 2 : フロントエンド（GitHub Pages）のデプロイ

### 2-1. プロジェクトルートへ移動

```powershell
cd C:\Users\takes\source\repos\KabuMemo
```

### 2-2. `index.html` の `<base>` タグについて

GitHub Pages では `<base href="/KabuMemo/" />` が必要だが、**対応方法はデプロイ方式によって異なる。**

| デプロイ方式 | 対応方法 |
|---|---|
| **GitHub Actions（Part 6）** | 手動変更不要。CI が自動で書き換えてビルドする |
| **手動デプロイ（2-5 の方法A〜C）** | ビルド前に手動で変更し、デプロイ後に元に戻す |

#### 手動デプロイの場合のみ実施

```html
<!-- 変更前（ローカル開発用・通常はこの状態を維持） -->
<base href="/" />

<!-- 変更後（GitHub Pages 用・手動デプロイ時のみ変更） -->
<base href="/KabuMemo/" />
```

> **注意:** デプロイ完了後は必ず `/` に戻すこと。戻し忘れるとローカル開発時に画面が表示されなくなる。

### 2-3. リリースビルド実行

```powershell
dotnet publish -c Release
```

出力先: `bin\Release\net10.0\publish\wwwroot\`

### 2-4. SPA ルーティング用に `404.html` を作成

GitHub Pages は存在しないパスへのアクセスを `404.html` にリダイレクトする。  
Blazor SPA のルーティングを機能させるため、`index.html` を `404.html` としてコピーする。

```powershell
Copy-Item "bin\Release\net10.0\publish\wwwroot\index.html"  "bin\Release\net10.0\publish\wwwroot\404.html" -Force
```

### 2-5. ビルド成果物を Git に反映

#### 方法A: `master` ブランチ / docs に成果物を配置する場合（推奨）

GitHub Pages の Source を「master ブランチ / docs」に設定している場合。  
`docs\` フォルダをリポジトリに含めてそのまま master へプッシュするだけでよい。

```powershell
# docs フォルダを作成してビルド成果物をコピー
New-Item -ItemType Directory -Force -Path "docs" | Out-Null
Copy-Item "bin\Release\net10.0\publish\wwwroot\*" "docs\" -Recurse -Force

# 変更をコミット＆プッシュ
git add docs/
git commit -m "deploy: release build"
git push origin master
```

> **メリット:** ブランチを切り替える必要がなく、ソースコードとビルド成果物を同じブランチで管理できる。

#### 方法B: ビルド成果物をリポジトリルートに直接配置する場合

GitHub Pages の Source を「master ブランチ / root」に設定している場合。

```powershell
# ビルド成果物をリポジトリルートにコピー
Copy-Item "bin\Release\net10.0\publish\wwwroot\*" "." -Recurse -Force

# 変更をコミット＆プッシュ
git add -A
git commit -m "deploy: release build"
git push origin master
```

#### 方法C: `gh-pages` ブランチ / root に成果物を配置する場合

GitHub Pages の Source を「gh-pages ブランチ / root」に設定している場合。

```powershell
# gh-pages ブランチが存在しない場合は作成
git checkout --orphan gh-pages
git reset --hard

# ビルド成果物をコピー
Copy-Item "bin\Release\net10.0\publish\wwwroot\*" "." -Recurse -Force

# コミット＆プッシュ
git add -A
git commit -m "deploy: release build"
git push origin gh-pages --force

# master ブランチに戻る
git checkout master
```

#### 方法D: `gh-pages` ブランチ / docs に成果物を配置する場合

GitHub Pages の Source を「gh-pages ブランチ / docs」に設定している場合。

```powershell
# gh-pages ブランチが存在しない場合は作成
git checkout --orphan gh-pages
git reset --hard

# docs フォルダを作成してビルド成果物をコピー
New-Item -ItemType Directory -Force -Path "docs" | Out-Null
Copy-Item "bin\Release\net10.0\publish\wwwroot\*" "docs\" -Recurse -Force

# コミット＆プッシュ
git add -A
git commit -m "deploy: release build"
git push origin gh-pages --force

# master ブランチに戻る
git checkout master
```

## Part 6 : GitHub Actions による自動デプロイ（推奨）

`master` ブランチへプッシュするたびに自動でビルド・GitHub Pages へデプロイする構成。  
**`<base href>` の手動変更は不要。** CI がビルド後に `/KabuMemo/` へ書き換える。

### 6-1. ワークフローファイルの内容

`.github/workflows/deploy.yml`（リポジトリに既に含まれている）。

```yaml
name: Deploy to GitHub Pages

on:
  push:
    branches:
      - master

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: false

env:
  FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Setup .NET
        uses: actions/setup-dotnet@v4
        with:
          dotnet-version: '10.x'

      - name: Publish
        run: dotnet publish -c Release

      - name: Set base href for GitHub Pages
        run: |
          sed -i 's|<base href="[^"]*"|<base href="/KabuMemo/"|g' \
            bin/Release/net10.0/publish/wwwroot/index.html
          grep 'base href' bin/Release/net10.0/publish/wwwroot/index.html

      - name: Upload Pages artifact
        uses: actions/upload-pages-artifact@v3
        with:
          path: bin/Release/net10.0/publish/wwwroot

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: Deploy to GitHub Pages
        id: deployment
        uses: actions/deploy-pages@v4
```

> **ポイント:** `dotnet publish` でビルドした後、publish 済みの `index.html` に対して `sed` で `base href` を書き換える。ソースの `wwwroot/index.html` は変更しない。

### 6-2. GitHub Pages の Source を GitHub Actions に設定（初回のみ）

`actions/deploy-pages` を使う構成では、`gh-pages` ブランチは不要。GitHub Pages ネイティブの配置を使う。

1. GitHub リポジトリの **Settings** → **Pages** を開く
2. **Source** を以下のように設定して **Save**

| 項目 | 設定値 |
|---|---|
| Source | `GitHub Actions` |

### 6-3. 通常のデプロイ手順（自動化後）

```powershell
git add -A
git commit -m "コミットメッセージ"
git push origin master
```

プッシュ後、GitHub の **Actions** タブで `Deploy to GitHub Pages` ワークフローが緑（✅）になれば完了。  
`build` → `deploy` の2ジョブが順に実行される。

## Part 7 : MD共有機能のセットアップ

MDファイルをユーザー間で共有する機能の初期設定手順。

---

### 7-1. KabuMemo-shared リポジトリの作成（初回のみ）

共有MDファイルの保存先となる専用リポジトリを作成する。

1. GitHub にログインし、右上の **＋** → **New repository** をクリック
2. 以下の設定で作成する

| 項目 | 設定値 |
|---|---|
| Repository name | `KabuMemo-shared` |
| Visibility | Public または Private |
| Initialize with README | 不要 |

3. **Create repository** をクリック

> アップロードされた MD ファイルはこのリポジトリの `shared-md/` フォルダに保存される。  
> `KabuMemo` 本体のリポジトリには影響しない。

---

### 7-2. GitHub PAT の作成（初回のみ）

KabuMemo-shared への書き込みに使用する Personal Access Token を作成する。

#### Tokens (fine-grained) の場合

1. GitHub → 右上アバター → **Settings**
2. 左下 **Developer settings** → **Personal access tokens** → **Tokens (fine-grained)**
3. **Generate new token** をクリック
4. 以下のように設定する

| 項目 | 設定値 |
|---|---|
| Token name | `KabuMemo-shared` など任意 |
| Expiration | 任意（90日推奨） |
| Repository access | Only select repositories → `KabuMemo-shared` を選択 |
| Repository permissions → Contents | **Read and write** |

5. **Generate token** → 表示されたトークンをコピー（一度しか表示されない）

#### Tokens (classic) の場合

1. GitHub → **Developer settings** → **Personal access tokens** → **Tokens (classic)**
2. **Generate new token** をクリック
3. Scopes で **`repo`** にチェック
4. **Generate token** → トークンをコピー

---

### 7-3. PAT 初期値の変更方法

PAT の初期値はソースコードの定数に記述されている。変更する場合は以下のファイルを編集する。

**ファイル:** `Services/GitHubService.cs`

```csharp
private const string DefaultPat = "github_pat_XXXX...";  // ← ここを変更
```

変更後はビルド・デプロイを実施すること（Part 6 参照）。

> PAT は localStorage に保存されていない場合のみコード内の初期値を使用する。localStorage に PAT が保存済みの場合はそちらが優先される。  
> 初期値を変更してデプロイしても、既に localStorage に PAT を保存済みのユーザーには反映されない。その場合は設定画面から手動で更新すること。

---

### 7-5. アプリの設定確認

1. アプリを開く（起動時に PAT が自動で設定される）
2. ヘッダーの **⚙** → **GitHub共有設定** をクリック
3. 設定画面で以下を確認する

| 項目 | 内容 |
|---|---|
| Personal Access Token (PAT) | 自動設定済み（変更する場合は入力して「保存」） |
| オーナー | `takeshitaj001-create`（変更不可） |
| リポジトリ名 | `KabuMemo-shared`（変更不可） |
| 共有フォルダ名 | `shared-md`（変更不可） |

4. **接続テスト** をクリックし「接続OK」と表示されることを確認する

> PAT を変更した場合は「保存」を押してから接続テストを実施すること。

---

### 7-6. MDファイルのアップロード手順

1. 詳細画面（任意の銘柄）を開く
2. **MDメモ** カードの **☁ 共有から選択** をクリック
3. モーダル上部の **📂 ファイル選択** でローカルの `.md` ファイルを選択する
4. 保存ファイル名を確認・必要に応じて変更する
5. **📤 アップロード** をクリック
6. 「アップロードしました。」と表示されれば完了

**アップロード時の制限事項**

| 項目 | 制限 |
|---|---|
| ファイル形式 | `.md` のみ |
| ファイルサイズ | 100KB 以内 |

---

### 7-7. 共有MDファイルの取込手順

1. 詳細画面（任意の銘柄）を開く
2. **MDメモ** カードの **☁ 共有から選択** をクリック
3. モーダルのファイル一覧から取り込みたいファイルの **取込** をクリック
4. モーダルが閉じ、MDメモ欄に内容が表示されれば完了

> **🔄 更新** ボタンを押すとファイル一覧を最新状態に更新できる。

## トラブルシューティング

### Worker デプロイ時に `code: 10034` エラー

Cloudflare アカウントのメールアドレスが未認証。  
`https://dash.cloudflare.com/` にログインしてメール認証を完了させる。

### GitHub Pages にアクセスすると 404 になる

- `wwwroot\index.html` の `<base href="/KabuMemo/" />` が設定されているか確認
- `404.html` が `wwwroot` 直下にコピーされているか確認
- GitHub Pages の Settings で正しいブランチが選択されているか確認

### 株価・企業概要が取得できない

- Worker が正常にデプロイされているか `Part 1-4` の疎通確認を実施
- `Services\StockApiService.cs` の `ProxyBaseUrl` が本番 Worker の URL になっているか確認

```csharp
private const string ProxyBaseUrl = "https://kabumemo-proxy.kabumemo.workers.dev";
```
