# KabuMemo 詳細設計書

## 1. システム概要

### 1-1. 目的

株式投資に関するメモ・銘柄情報を一元管理する個人向け Web アプリ。  
サーバーサイド処理を持たない静的 SPA として GitHub Pages で動作し、データは全てブラウザの localStorage に保存する。

### 1-2. システム構成

```
[ブラウザ]
  Blazor WebAssembly (.NET 10)
  ├─ 銘柄一覧画面 (Home.razor)
  └─ 個別銘柄詳細画面 (StockDetail.razor)
         ↓ HTTP (fetch)
[Cloudflare Worker]
  kabumemo-proxy.kabumemo.workers.dev
  ├─ Cookie + Crumb 認証管理
  ├─ CORS ヘッダー付与
  └─ レート制御・フォールバック
         ↓
[外部 API]
  ├─ Yahoo Finance v7/v8/v10 (株価・チャート・配当・企業概要)
  ├─ Yahoo Finance Search v1  (銘柄コード検索)
  ├─ Yahoo Finance Japan      (銘柄名検索)
  ├─ irbank.net               (適時開示スクレイピング)
  └─ MyMemory API             (英日翻訳)
```

### 1-3. 技術スタック

| 区分 | 技術 | バージョン |
|---|---|---|
| フロントエンド | Blazor WebAssembly | .NET 10.0.7 |
| スタイリング | Bootstrap 5 + カスタム CSS | - |
| API プロキシ | Cloudflare Workers | - |
| ホスティング | GitHub Pages | - |
| データ永続化 | localStorage (JS Interop) | - |
| CI/CD | GitHub Actions | - |

## 4. サービス層

### 4-1. StockService（localStorage 操作）

`Services/StockService.cs`

#### 概要

localStorage への銘柄データの読み書きを担当。JS Interop 経由でブラウザの localStorage を操作する。

#### DI 登録

```csharp
builder.Services.AddScoped<StockService>();
```

#### メソッド

| メソッド | 戻り値 | 説明 |
|---|---|---|
| `GetAllAsync()` | `Task<List<StockItem>>` | localStorage から全銘柄を読み込む |
| `SaveAsync(List<StockItem>)` | `Task` | 全銘柄を localStorage に書き込む |

#### 実装詳細

```
GetAllAsync:
  1. JS.InvokeAsync<string>("localStorage.getItem", "kabumemo_stocks")
  2. null または例外 → 空リストを返す
  3. JSON.Deserialize<List<StockItem>> で復元

SaveAsync:
  1. JSON.Serialize(items)
  2. JS.InvokeVoidAsync("localStorage.setItem", "kabumemo_stocks", json)
```

### 4-2. StockApiService（外部 API 呼び出し）

`Services/StockApiService.cs`

#### 概要

Cloudflare Worker を経由して Yahoo Finance・irbank.net からデータを取得する。  
HttpClient のタイムアウトは 10 秒。

#### DI 登録

```csharp
builder.Services.AddScoped(_ => new StockApiService(
    new HttpClient { Timeout = TimeSpan.FromSeconds(10) }
));
```

#### エンドポイント一覧

| メソッド | Worker エンドポイント | 戻り値 | 説明 |
|---|---|---|---|
| `FetchQuoteAsync(code)` | `GET /api/quote/{code}` | `QuoteResult` | 現在値・各種指標 |
| `FetchChartAsync(code)` | `GET /api/chart/{code}` | `ChartResult` | 日次株価（1年分） |
| `FetchDividendsAsync(code)` | `GET /api/dividends/{code}` | `DividendResult` | 配当推移（5年） |
| `FetchSummaryAsync(code)` | `GET /api/summary/{code}` | `SummaryResult` | 企業概要・決算日 |
| `FetchTdnetAsync(code)` | `GET /api/tdnet/{code}` | `IrFetchResult` | 適時開示一覧 |
| `FetchSearchResultsAsync(query)` | `GET /api/name/{query}` | `List<YahooSearchQuote>` | 銘柄検索 |
| `FetchJapaneseNameAsync(code)` | `GET /api/name/{code}` | `string?` | 銘柄和名取得 |

#### 結果ラッパー型

全 API の戻り値は以下のパターンに統一されている。

```csharp
class XxxResult {
  bool Success      // データ取得成功かどうか
  TData? Data       // 成功時のデータ
  string? Error     // 失敗時のエラーメッセージ
}
```

| 型 | 成功時のデータ型 |
|---|---|
| `QuoteResult` | `StockQuote` |
| `ChartResult` | `List<ChartPoint>` |
| `DividendResult` | `List<DividendEntry>` |
| `SummaryResult` | `CompanySummaryResponse` |
| `IrFetchResult` | `List<IrInfo>` |

#### エラーハンドリング

各メソッドは以下の例外をキャッチし、`Result.Fail()` に変換する。

| 例外 | エラーメッセージ |
|---|---|
| `HttpRequestException` | `HTTP エラー(HTTP {status}): {message}` |
| `TaskCanceledException` | `タイムアウト（10秒）` |
| `Exception` | `{ExceptionType}: {message}` |

#### HTML パース（適時開示）

`ParseTdnet(html)` メソッドが irbank.net の HTML を解析し `List<IrInfo>` に変換する。

```
1. <tbody>...</tbody> を正規表現で抽出
2. <tr>...</tr> を列挙
3. 各行の <td> を3列取得（日付, カテゴリ, タイトル+URL）
4. タイトルは <a href="..."> から抽出
5. URL が相対パスの場合 https://irbank.net を補完
```

#### 株価一括更新フロー

```
UpdateAllPrices():
  isUpdatingPrices = true
  foreach (stock in stocks):
    updateProgress = "{i+1}/{total}"
    result = await FetchQuoteAsync(stock.Code)
    if result.Success:
      stock.CurrentPrice = result.Quote.Close
      stock.PriceChange = result.Quote.Change

  isUpdatingPrices = false
```

## 6. Cloudflare Worker 設計

### 6-1. 概要

`worker/index.js` に実装される Cloudflare Worker。  
Worker 名: `kabumemo-proxy`  
公開 URL: `https://kabumemo-proxy.kabumemo.workers.dev`

#### CORS 設定

```javascript
const CORS = {
  'Access-Control-Allow-Origin': '*',
  'Access-Control-Allow-Methods': 'GET, OPTIONS',
  'Access-Control-Allow-Headers': 'Content-Type',
};
```

OPTIONS リクエストには 204 No Content を返す。

### 6-2. セッション管理

Yahoo Finance は Crumb + Cookie による認証が必要。  
Worker インスタンス内にセッションをキャッシュして再利用する。

```javascript
let cachedSession = null;  // { crumb, cookies }
```

#### refreshSession() フロー

```
1. finance.yahoo.com/ にアクセス → Cookie 取得
2. レスポンスが同意ページ (csrfToken / collectConsent) の場合:
   - consent.yahoo.com/v2/collectConsent へ POST（同意フォーム送信）
   - Cookie を mergeCookies() でマージ
3. query1/query2 で /v1/test/getcrumb を試行 → crumb を取得
4. 取得成功 → cachedSession = { crumb, cookies }
5. 取得失敗 → Error をスロー
```

#### セッションリフレッシュのトリガー

- `cachedSession === null`（初回）
- API レスポンスが HTTP 401
- v7 quote の result が空配列（crumb 失効の可能性）

### 6-3. エンドポイント詳細

#### GET /api/quote/{code}

Yahoo Finance v7 API で銘柄の現在値・各種指標を取得。

```
URL: query1.finance.yahoo.com/v7/finance/quote
  ?symbols={code}.T&crumb={crumb}&lang=ja&region=JP

フォールバック（result が空 / 認証失敗）:
  1. refreshSession() → v7 再試行
  2. v8 chart API (interval=1d, range=10d) で最新終値取得
  3. v10 quoteSummary (modules=price) にフォールバック
```

#### GET /api/chart/{code}

```
URL: query1.finance.yahoo.com/v8/finance/chart/{code}.T
  ?interval=1d&range=1y&crumb={crumb}

レスポンス変換:
  timestamps[] + indicators.quote[0].close[]
  → [{ date: "YYYY-MM-DD", close: 1234.5 }, ...]
```

#### GET /api/dividends/{code}

```
URL: query1.finance.yahoo.com/v8/finance/chart/{code}.T
  ?events=div&range=5y&interval=1mo&crumb={crumb}

レスポンス変換:
  events.dividends（Unix タイムスタンプ → 支払日）
  → 4月始まり年度（月>=4 → 当年, 月<4 → 前年）でグループ集計
  → [{ year, amount, interimAmount, finalAmount }, ...]
     interimAmount: 7月以降払い（中間配当）
     finalAmount:   6月以前払い（期末配当）
```

#### GET /api/summary/{code}

```
URL: query1.finance.yahoo.com/v10/finance/quoteSummary/{code}.T
  ?modules=assetProfile,calendarEvents&crumb={crumb}

翻訳:
  longBusinessSummary（英語）
  → 450文字チャンクに分割
  → MyMemory API (api.mymemory.translated.net) で逐次翻訳
  → 翻訳失敗時は原文を返す

レスポンス:
  { description, employees, city, country, earningsDate }
```

#### GET /api/tdnet/{code}

```
URL: irbank.net/{code}/tdnet/

HTML から正規表現でパース:
  <tbody> → <tr> → <td>[0]日付 [1]カテゴリ [2]<a>タイトル</a> → URL
```

#### GET /api/name/{query}

```
数値コードの場合:
  → query1.finance.yahoo.com/v1/finance/search?q={code}.T
  → .T で終わるシンボルのみを返す
  → 0件時: { symbol: "{code}.T" } のダミーを返す

日本語テキストの場合:
  1. finance.yahoo.co.jp/search/?query={query}
     HTML から "code","marketName","name" パターンを正規表現で抽出
  2. 0件時フォールバック: Yahoo Finance US search で .T フィルタ
```

## 7. ルーティング設計

`App.razor` が `Router` コンポーネントでルーティングを管理。  
アセンブリスキャンにより `Pages/` 配下の `@page` ディレクティブを自動認識。

| URL パターン | コンポーネント | 説明 |
|---|---|---|
| `/` | `Pages/Home.razor` | 銘柄一覧画面 |
| `/stock/{Code}` | `Pages/StockDetail.razor` | 個別銘柄詳細 |
| その他 | `Pages/NotFound.razor` | 404 ページ |

### SPA ルーティング（GitHub Pages 対応）

GitHub Pages は SPA のディープリンクに対応していないため、以下の対策を実施。

```
1. 404.html に index.html と同一内容を配置
2. 404.html 内のスクリプトが ?p= パラメータでパスを渡す
3. index.html のスクリプトが ?p= を読み取り history.replaceState() で URL を復元
4. Blazor Router が復元後の URL でルーティングを解決
```
